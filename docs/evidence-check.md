# 来源删减检查 v0.2

“删掉这条消息，你的投资结论还成立吗？”是当前新增入口。给定人工确认的命题、固定规则、同一观察截止时间和一组**合成**记录，比较删去某来源前后的成立、不成立或未知状态，并保留每条资料被纳入或排除的理由。

这是证据敏感性检查，不是严格因果归因、价格预测、收益回测或 alpha 证明。原有合成价格实验保留在独立页签。本模块不调用模型、网络、账号或订单服务。

## 运行与复核

打开 `dist/index.html`：编辑论点 → 明确阶段、期间和数值门槛 → 人工确认 → 切换公开/全部合成来源或取消一个来源 → 导出 JSON。

```sh
npm test
npm run build
node src/evidence-cli.mjs examples/evidence.json
node src/evidence-cli.mjs examples/evidence.json public issuer-report
node src/evidence-cli.mjs examples/evidence.json all
```

导出包含整个合成数据集（也包括被排除的记录）；“仅公开”是评价范围开关，不是文件脱敏功能。未来若接入真实资料，必须另行实现授权范围与导出许可检查。

CLI 输出完整对照报告，并把成功、未知、冲突和失败运行留在 `runtime/evidence-checks.jsonl`。使用原有 `readJournal()` 可检查完整性。日志是本地可变文件，没有外部见证。浏览器保留当前会话的检查与失败，导出时包含这些版本；刷新后清空。不要把个人论点或本地运行记录直接加进公开包。

默认合成样例：公开季度报告与同源转载均称收入 120 万元；门槛为 100 万元，结果成立。删除该报告的来源组后，两份载体一起被排除，签约公告不能补作收入证据，因此变为未知。纳入全部样例时，一条**虚构非公开记录**声称完整收入 70 万元，结果是冲突且未知。未来更正和缺少可得时间的摘录明确排除。

## 严格契约

权威、可执行校验器在 `src/evidence.mjs`；完整示例在 `examples/evidence.json`。未知字段、记录到载体的引用错误、重复身份、非法日期、字符串数值及未经支持的真实数据类别均拒绝。父链错误保留在逐条排除原因中，不丢弃失败证据。数据集及报告使用 schema 2，引擎 `evidence-check/0.2.0`；旧 schema 1 不静默升级。只允许 `kind: synthetic`；未来公开资料适配必须先补许可与来源核验，不能改一个标签就当已获验证。

请求必需 `claim`、`dataset`、`asOf`，可选 `visibility: public | all` 与 `excludedOrigins`。时间必须为带毫秒的规范 UTC；缺失的证据时间显式写 `null`。

| 对象 | 关键字段与语义 |
| --- | --- |
| claim | `id/version`，`confirmation: human_confirmed | ai_candidate`，原论点，实体、指标、阶段、期间开始与结束（期限）、单位、`operator: gte`、门槛、否证说明 |
| source | 载体 `id`、描述性 `originId`（不作判据）、标题、可见性、合成定位和 `provenanceId`；可见性和定位必须匹配所引用节点 |
| provenance | `id` 为其他字段规范 JSON 的 SHA-256；`kind: primary / repost / ai`，`parentId` 为父节点哈希，`originId` 仅根节点填写，`visibility/url` 绑定节点元数据；每个派生节点最多一个父节点 |
| observation | 记录 `id`、载体 `sourceId`、原始来源的 `sourceVersion`、人工确认状态，实体/指标/阶段/期间/单位，`value`，`coverage`，发生/发布/首次可得时间和合成短摘录 |
| report | 完整输入、合成来源登记副本及版本/hash、固定协议、双侧结论、冲突对、每条记录的角色/完整父链/排除原因/hash、实际根源组数、变化解释和能力边界 |

`adoption`（采用）、`signed`（签约）、`accepted`（验收）、`recognized_revenue`（收入确认）、`cash_received`（回款）互不替代。实体、指标、阶段、期间和单位必须全部精确匹配；不跨币种、不隐式换算、不从关键词猜测事实。UI 演示固定合成公司及季度金额；其他指标、自然语言解析和真实来源导入未实现。

`thesis` 与 `falsification` 是人工确认的说明文字，不参与自然语言推理。唯一可执行谓词是明确的数值门槛：`value >= threshold`。`complete` 表示人工标记为该期间的完整总量，低于门槛才可否证；`lower_bound` 未达到门槛只表示未知。`null` 从不变成 0；明确测得的 0 才按零计算。判断质量仍依赖口径、完整性、抽取值、版本和历史时间声明准确，软件没有实际检索文件以验证这些声明。

## 来源角色、父链与信任边界

人工确认分为命题接受和抽取复核，均不能改变来源角色或登记新的独立根源。AI 回答、人工转述与转载使用 `ai/repost` 节点，沿 `parentId` 追溯已登记原始来源；它们仅展示追溯信息，`included: false`，不参与数值支持、否证、冲突或独立来源计数。即使原始记录缺失，也不能用转述补足。需要检查其矛盾时须回到原始资料，当前不推断转述内容真伪。

根节点的哈希与实际来源组绑定在 `src/synthetic-provenance.mjs` 的内置登记表，版本为 `synthetic-roots/1`。它只登记虚构合成样例，不是现实来源核验名单。请求不能覆盖该表；给 AI 改名、改 `originId`、确认内容或重新计算一个伪造根节点哈希，都不会新增已登记来源。引用相同登记根源的载体只计一个来源组，删除使用解析得到的实际根源组。两份分别登记且均有可用原始记录的合成来源可计两个组，但仍不投票或声称统计独立。

父节点哈希绑定其角色与祖先。对既有节点原位修改角色或父链会失配；父链有环、缺节点、没有原始终点或根源不在登记表中时，该记录根源未知、不纳入支持。有其他可用原始证据时仍可判断；全部证据都不合格时输出未知。派生来源继承整条链的非公开限制，公开转述不能使非公开根源通过公开范围过滤。多来源混合文章暂不自动拆分或生成新根源，需要逐个原始证据分别记录。

**这里的不可覆盖是相对于已有哈希引用和当前程序内置登记表的完整性校验，并非不可修改的存储。**手动编辑原始文件、代码或登记表，或把某条编造事实伪装成现有已登记原始来源的记录，仍可绕过此本地模型。哈希既不证明历史真实，也不证明文本来自所称机构；重新编造整份文件后重算哈希不能据此获得真实性。没有可靠识别所有文本伪造、外部签名、外部时间戳、联网来源鉴别或文档到抽取片段的真实性绑定。真实接入前必须另建获授权检索、根源审核登记与受保护历史；本次继续只接受合成数据。

## 时间、修订与冲突

1. 先核验父链与根源登记，再按来源范围、来源删减、口径、确认状态和时间过滤。发生、发布、首次可得时间任一缺失或晚于 `asOf` 均排除；AI／转载仅供追溯。
2. 再从当时已可得的原始记录选择实际根源的最高版本。转载展示其引用的原始版本，不能用高版本号取代原始记录；旧转载在已知更正后标为已取代。迟到修订不能回填过去，更正为未知值也不能继续沿用已失效旧值。
3. 同来源组归并，不以转载或独立来源的数量投票。两个完整总量数值不同，或完整总量低于另一个下界，都显示冲突，即便二者同样高于门槛。不同下界可同时成立。
4. 有任何数值冲突就未知；无冲突且存在达标的可用证据则成立；存在低于门槛的完整总量则不成立；其余未知。候选命题或未确认抽取不能生成接受的结论。

来源之间是否存在未披露共同上游仍无法自动识别。当前父链只校验已记录的合成谱系，不证明真实世界独立性。排除某证据不会证明它无用，结论未变化也不证明信号无增量。导出复核需要相同引擎和登记版本；报告内附登记副本用于核对，不能将导出里的任意新登记注入引擎。旧 v0.1 报告需保留的旧源码复核，不能用 v0.2 静默替代其结论。

## 与既有研究框架的边界

见潮原 `src/core.mjs` 的模拟记账、成本、候选预算和哈希工具继续使用；新模块复用 `digest`、字段校验以及 `src/log.mjs`，没有另建回测引擎。另一个已有 Python 离线框架已经实现收到时刻、修订、隔离切分、成本与一次性 holdout 控制，在本次独立参考副本完成 23 项合成测试。它尚未接入此 UI，未复制其历史归因材料或用户原始数据。

**尚未实现**：严格 price-only 对照、价格+事件增量消融、真实公开来源导入、N3 历史反例的证据核对、跨进程实验预算、外部时间戳、独立前瞻检验、SQLite 数据库。这里没有将“删来源”的结果冒充上述检验；也没有新增真实回测数字。
