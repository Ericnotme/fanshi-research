# Security and privacy boundary

The local evidence-check workspace accepts only synthetic datasets with strict field validation. It has no live-source importer, model extraction, price forecast or execution adapter. Dataset schema 2 uses content-addressed provenance nodes with explicit primary/repost/AI roles and parent hashes. Only primary records whose chain terminates at a root pinned in the bundled synthetic registry can contribute factual support. AI/reposts remain trace-only after human confirmation; they cannot replace unavailable primary records. Source `originId` is a non-authoritative label. Cycles, missing nodes, in-place hash mismatches and unregistered roots are excluded with reasons. A request cannot supply or overwrite the registry.

This is a local synthetic trust model, not proof of real source authenticity, institutional independence, accurate extraction or immutable storage. Metric scope, values, versions, confirmation and historical times remain input declarations. An editor can alter code/registry/files, or falsely label an observation as an existing registered primary; no hash can distinguish that forgery from authorized input. A rewritten graph with newly computed hashes is a new declaration, not proof of its history. Human confirmation does not authenticate provenance. Real ingestion would need authorized source retrieval, evidence-to-document binding, independently reviewed root registration and externally protected history. Text similarity is not used as a reliable forgery detector. Conflicting values yield unknown; a positive result only satisfies the specified numerical predicate. All reports explicitly deny causal attribution, validated alpha and trade eligibility. User-entered thesis text is rendered with textContent and remains in session memory until an explicit JSON export. It must not enter source control or the public allowlist.

CLI evidence checks append successful, unknown, conflicting and failed attempts to the existing local hash-chain journal. Parsing errors do not echo user inputs. No private conversation, original message ID, investment account record or historical attribution file is bundled with this feature. The six Skills are public-safe methods with synthetic examples and separated user/AI attribution; their runtime compatibility and real-world effectiveness are distinct from structure and synthetic-use checks.

The local demo has CSP `connect-src 'none'` and works from a local file. Its evaluators use synthetic data. A separate editorial public-research case contains concise self-written summaries, official source links and page locators; it never enters the synthetic engine. It has no private input, historical signal eligibility, official-document byte hashes or tested returns. Unknown first-public timestamps remain null. It does not include article/PDF copies or imply that publicly readable material has a redistribution license. Offline CLI and MCP entrypoints do not import the network adapter. Source/documentation/portfolio links are ordinary user-initiated navigation. There is no brokerage adapter, financial account login, order submission, funds transfer, analytics, upload endpoint or device driver.

An optional Node-only Responses HTTP adapter is available through a separate explicitly enabled CLI. Only that path lazily reads the user's `OPENAI_API_KEY` environment variable; it never loads credential files, browser sessions or keychains. It sends a fixed synthetic hypothesis prompt to the official endpoint, refuses redirects/custom endpoints, caps requests/output tokens/body size, and reserves an estimated spend allowance before each attempt. Estimates are not provider billing guarantees or cross-process limits. Timeouts/network failures are not automatically retried, since remote billing may already have occurred. No real credentials or paid API calls were used in release validation. See [provider limits](docs/openai-provider.md).

Model output is untrusted data. Only eight bounded parameter combinations are admitted; executable text is not evaluated. The evaluator is fixed source code. Refusals, incomplete responses, unknown fields, duplicate candidates and expanded search budgets fail closed. API audit events never persist request headers, keys, raw response bodies or refusal text. Journal write failures stop the provider. Runtime files must remain local; do not expose this adapter as an unauthenticated web endpoint.

The phone module is a non-executable plan interface. Its public/private-context flags are caller declarations, not a verified privacy classifier. It must not be wired to a device without an independently reviewed public-page boundary and explicit authorization. Unknown or personal contexts stop the plan. No financial account action exists.

Browser storage is local, mutable and limited to synthetic experiment metadata. Node logs have an integrity hash chain and an exclusive writer lock; an administrator can rewrite them and recompute hashes. A crash may leave a lock or partial record. Preserve the files and inspect them before recovering; do not delete history just to get a green check.

Publish only paths in `PUBLIC_FILES.json`. Runtime logs, private files, credentials, screenshots of personal pages, local config, raw research data and Git history from other projects must never be copied. The included scanner is a useful pattern check, not a guarantee of privacy or a security certification.

Use GitHub issues for non-sensitive reproducible bugs. Do not paste credentials, personal financial data or device identifiers into issues.
