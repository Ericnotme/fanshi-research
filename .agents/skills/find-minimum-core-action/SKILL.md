技能自身的署名与来源说明：鲜唯佳与 AI 协作。用户提供问题选择、约束、纠正与取舍；AI 起草抽象结构、字段与测试。方法候选不代表已验证现实效果，也不代表临床或投资资质。此说明仅描述本技能，不可照搬为新任务材料的作者或贡献；新材料逐项按其证据归属，未知保持未知。第三方方法保留原作者归属。

遵循当前用户授权与任务范围。已有明确授权的工作继续执行；仅在缺少必要授权时暂停相应外部动作。本技能不单独授权发布、付款、联络第三方或删除原始资料。

输出可复核结果时，记录版本、输入范围、证据引用、假设、决定、限制及实际执行状态（passed / failed / blocked / inconclusive / not_run）。预测本身的 pending 或未命中状态与技能执行状态分开。未知数值用 null 并保留原因；真实零、未知、未核实、不可访问和不适用不得合并。私有来源与公开合成案例分开，失败与旧版本不被覆盖。

### 触发器

产品反复改审美、功能越做越多、作品集难以取舍，或用户要求找出像搜索框一样简单直接的核心功能时。

### 输入

- 产品或作品集清单与可访问入口
- 各产品真实能完成的任务
- 用户目标、已有反馈与可信使用证据
- 现有版本和可回退方式
- 哪些取舍需要用户决定

### 步骤

1. 逐一体验当前核心功能。打不开或无法完成的产品明确标注，不能由名字想象体验。
2. 对每项功能写出最短链条：“用户带着什么问题来 → 做一个什么动作 → 得到什么可感知结果”。
3. 根据任务价值、理解成本、完成成本、结果可信度、重复使用理由列出候选；缺少用户证据时使用假说，不伪造评分。
4. 找出最小可独立兑现价值的功能，写清它需要保留哪些依赖、限制和错误处理。简化界面不能隐藏必要解释。
5. 提供少量不同的收缩方案及代价：优先保留什么、可暂缓什么、什么信息仍不足。
6. 先给可审查的取舍清单，等待用户对重大产品删减作决定。实施前保留旧版，再比较核心任务是否更容易完成。

### 输出

`core_action_shortlist`：功能、目标问题、最短动作、可感知结果、支持证据、保留依赖、暂缓内容、风险和待决定项。

`before_after_test`：同一任务的步骤数、完成率或观察记录，标注是否实测；审美偏好单列。

### 失败条件

- 把“极简”理解为只剩一个输入框，核心能力却不兑现
- 未经用户决定就删除站点、数据或重大功能
- 把 AI 喜欢的视觉样式当成用户验证过的亮点
- 只比较外观，不检查任务完成与错误处理

### 验证

完成任务后用 [合成案例](references/test-cases.md) 检查成功、边界和反例。测试用例不等于通过记录；未运行标记 not_run。

### 来源与贡献

用户明确提出从自己的作品集中找最大亮点、寻找最有搜索框式简洁感的功能，并保留最终删减决定。这个方向与决策边界来自用户；分析字段、流程和测试由 AI 起草。通用极简设计思想不宣称为个人首创。
